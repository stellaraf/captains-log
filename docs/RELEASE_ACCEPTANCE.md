## Evidence rules

Status vocabulary:

- **DEV**: a related path has retained real development-stack evidence; production appliance acceptance remains open.
- **PARTIAL**: some code, UI, documentation or tests exist, but material implementation or verification remains.
- **OPEN**: no completed implementation or authoritative acceptance evidence located.
- **UNVERIFIED**: implementation/recipe exists; execution on the required environment is not demonstrated.
- **OPTIONAL**: the specification expressly says optional, preferred, practical, or where validated; applicability and the actual result must be stated.

For each accepted requirement retain: source commit, artifact SHA-256/signature and immutable image digests; exact OS/packages/module versions; guest/hypervisor and allocated CPU/RAM/disks; initial state; command/API/browser steps; timestamps; measured output; pass/fail criterion; failure/recovery result; final persisted state. Redact secrets and private log content while retaining sanitized fixtures and public summaries. Private evidence must remain available to the release reviewer without placing credentials in source control.

Authority is specific to the claim. A real socket proves transport behavior, not a hypervisor import. A schema unit fixture proves a controlled mapping, not actual PAN-OS release compatibility. A disabled SAML provider configuration proves configuration, not external sign-in. A generated archive of blank disks proves packaging mechanics, not that Rocky boots. Mocked storage/update transactions, shell syntax checks, flags, screenshots and successful builds cannot prove encrypted guest growth, host FIPS, compliance remediation, recovery or database upgrades.

## Decisions and blockers that must remain visible

1. The deployable product requires an installed and booted **Rocky Linux 9 x86_64** guest, qualified strict-FIPS Keycloak/JVM/providers, HTTPS edge, immutable application/database images, first boot and host-to-API control/status integration. Installing Rocky alone does not complete the appliance.
2. Production Quadlets split `serve` and `ingest`. At this snapshot, `internal/api/server.go` returns empty collector metrics/listeners when `Collector` is absent, and the host security/update endpoints are explicitly unconnected. Docker's combined `all` role does not prove this production topology works.
3. Storage is not complete without real first-boot enlargement, later online growth, additional-disk enrollment, LUKS recovery, UI confirmation and crash/reboot tests. Unit plans must not be represented as those tests.
4. Emergency Traffic-first purge, protected minimum retention, and historical retention-policy changes need implementation/acceptance. Current bounded spool and warning labels do not meet emergency disk policy requirements.
5. The complete sizing engine requires measured 1h/24h/7d averages and 1m/5m/1h peaks. Inventory `peak_eps` currently returns null. The API's net `system.parts` growth is not a sufficient long-term ingest-storage estimate during TTL/merge activity; reconcile it with the written-byte methodology in [STORAGE_SIZING](STORAGE_SIZING.md).
6. Local passkeys/recovery codes, AD/LDAPS plus Keycloak MFA, generic OIDC, generic/manual SAML and external tenant sign-in remain open. Okta/Entra configuration checks cannot close federation gates.
7. GitHub discovery/download and automatic compatible installation are implemented in source with a 15-minute default cadence, superseding the original daily requirement. Qualified transaction adapters, managed database/identity upgrades, OS/kernel reboot and end-to-end backup/restore remain open. The development `/api/updates` reports `not_connected`; source now bridges measured host channel status without treating configuration as runtime proof.
8. **100M records is mandatory.** The 1B benchmark is preferred; 30/90-day equivalent datasets are requested where practical. The prior scratch-space guard is a reason to obtain adequate test capacity, not to redefine success as 10M.
9. The requested Previous Application column exists in UI/storage but no parser field supplies it at this snapshot. Verify whether the supported native layout can provide it; document an honest unavailable field instead of deriving a fabricated value.
10. Host networking/DNS/NTP, certificate lifecycle, baseline selection, retention, storage, updates and recovery must be manageable without requiring the administrator to become a Linux/database/Keycloak operator. Documentation that sends normal users to shell commands or the Keycloak console is not the final workflow.

## Closing the release

The release reviewer must reconcile this matrix with the unchanged full specification and all accepted user steering, not with the subset already implemented. Add dated receipts and change each row only when the work and applicable negative/recovery tests are complete. Record any genuinely conditional feature's applicability explicitly. A blocker due to test capacity, provider tenant access, hypervisor access or licensed content must state the exact dependency and preserve the requirement; it is not a successful result.

The final review requires the signed deployable artifact, exact supported-platform matrix, current vulnerability and license review, reproducible build/test instructions, complete acceptance receipts, honest remaining limitations for optional support, and the user's explicit sign-off. No deployment recipe, progress screenshot or passing unit count is a substitute for that result.
